- Solana secondary sales use Core TransferDelegate approvals to the platform key plus a buyer-signed split payment verified server-side in `marketplace-purchase` before delivery — no custom escrow program needed, NFT stays in seller wallet until sold.
- NFT listing validation uses the shared chain-aware identifier resolver; Solana approvals require the individual asset address, not a collection contract, so wallet-to-listing handoffs must preserve `asset_id`.
- ApeChain drops: creators deploy their own `LilyApeDrop` ERC-721 (source `src/chains/apechain/LilyApeDrop.sol.txt`, compiled ABI/bytecode in `dropArtifact.ts`) from their wallet — no factory, so no platform-deployed contract is needed; platform fee is split inside `mint()`. Recompile with solc 0.8.24 if the source changes.
- Generator review grids paginate and unmount off-page artwork; the shared compositor reuses its canvas and caches source images per run to avoid accumulated image-decoding memory.
- ApeChain generator recovery stores configuration, source Files, and generated artwork in browser IndexedDB before review, rather than relying on count-only localStorage summaries, so reloads can restore editable work.
- Wallet Gallery uses current-owner indexers via useWalletNFTs for Solana and Robinhood only; unsupported chains must never fall through to Solana or present app purchase records as proof of ownership. Inventory remounts on wallet/chain changes to isolate pending requests and previews paginate to bound decoded artwork memory.
- Collectible details retain indexed ownership and metadata; marketplace links resolve canonical asset identity to minted_nfts.id and an active unexpired nft_listings row. Marketplace listing deep links fetch by exact listing ID independently of browse filters.
- Live chat inventory uses the authenticated session UUID, never the wallet address, for recorded shop purchases and follow-based channel emotes; recent selections must match freshly loaded inventory to avoid stale access.
- Music launches persist permanent audio links in collection_audio_metadata and per-track titles/descriptions keyed by artwork_id in collections.artworks_metadata, so public collection playback can use published data without local draft files.
- Watch tipping reuses TipButton with streams.user_id and streams.id so payout lookup stays on the existing protected server path.
- Streamer wallet lookups require an actual auth session and explicitly send its access token, with one refresh retry; the function verifies authenticated claims before accessing payout data so guest API keys never substitute for user identity.
- Stream status is classified only by `resolveStreamStatus` in `src/lib/streamStatus.ts`, shared by the Streams filters, cards, and Watch page, so a stream's live/scheduled/finished label cannot disagree between pages; creators announce through `streams.scheduled_at`, which the public read policy lists so collectors can see a stream before it starts.
- Production (publish) Vite builds must validate the generated public Cloud connection environment (from .env files or process env) before bundling; fail on missing settings rather than publish an app that crashes before mounting. Never gate development-mode builds — the platform's preview build wraps vite.config with its own config and supplies settings separately. Do not hardcode connection fallbacks or edit the managed client/environment files.
- Reown AppKit is the primary wallet connector for Solana and all EVM chains (Monad, Robinhood Chain, ApeChain, Ethereum); networks are registered once in src/integrations/reown/appkit.ts and WalletProvider derives chainType from Reown's active namespace/chain id. XRPL stays on its own wallets because Reown has no XRPL adapter.
- Collection hard deletion uses verified schema links (mint transactions via session_id and sessions via collection_address); detach shared shop, raffle and governance references, and preserve shared buybacks, blind boxes and homepage cards so deleting one collection cannot remove unrelated records.
